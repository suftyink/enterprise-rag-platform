# 09: 实施紧急撤回与修复发布

**What to build:** 让安全响应者或授权知识管理员在发现敏感、错误或违规内容时立即阻止该文档作为员工答案证据，并异步完成向量清理、Release 降级标记和修复候选构建。

**Blocked by:** 06 / 原子激活候选 Release.

**Status:** resolved

- [x] 紧急撤回立即写入数据库支持的检索排除状态，不等待向量数据库删除完成。
- [x] 检索结果在返回前执行活动 Release 成员关系、actor scope 和紧急排除检查，被撤回文档不能出现在引用中。
- [x] 撤回影响当前活动语料时，Release 被标记为 DEGRADED 或 readiness stale，并产生高优先级审计/运行信号。
- [x] 操作者可根据风险暂停相关 rollout；系统不会自动删除历史证据或破坏回滚产物。
- [x] 物理向量和对象清理通过可重试异步任务完成，失败可观测且不会恢复文档检索资格。
- [x] 系统创建或提示创建不包含该文档的修复候选，并复用未受影响的兼容产物。
- [x] 内部 Web 工作流证明撤回后立即不再引用目标文档，同时清理任务仍可处于排队或运行状态。

## Answer

系统管理员可从治理界面走紧急撤回：先通过原生命周期立即写入 WITHDRAWN 并排队物理清理，再把活动 Release 标记 DEGRADED、rollout 置 PAUSED。检索和生成前复核都要求活动成员关系且排除 WITHDRAWN，因此无需等待向量删除即可止血。

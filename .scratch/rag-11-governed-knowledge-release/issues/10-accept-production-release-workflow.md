# 10: 贯通生产类发布验收

**What to build:** 在生产类环境用代表性管理员和员工身份贯通知识治理、候选构建、评测门禁、激活、灰度、紧急撤回和回滚，形成可审计的内部生产试点开放证据。

**Blocked by:** 07 / 回滚到上一 Release; 08 / 按员工组灰度并支持暂停; 09 / 实施紧急撤回与修复发布.

**Status:** claimed

- [ ] 自动化内部 Web 工作流覆盖从无 readiness 的治理准备到候选 Release 激活的完整正常路径。
- [ ] 自动化验收覆盖越权治理、候选漂移、评测失败、证据过期/错配、激活故障和 rollout 暂停等失败路径。
- [ ] 自动化验收覆盖增量产物复用、不兼容契约全量重建、原子回滚和紧急撤回即时失效。
- [ ] 所有关键动作可通过 Release、报告、actor、scope、reason 和 trace 关联，且日志、报告和审计不包含禁止的内容字段。
- [ ] 使用真实 OIDC 身份、PostgreSQL、Redis、对象存储、向量基础设施、workers、模型路由和代表性语料完成生产类人工验收。
- [ ] 最终 `PilotReadiness` PASS、人工批准、rollout 范围、容量、监控负责人和回滚负责人均绑定同一活动 Release。
- [ ] 验收报告明确记录未完成、失败或不适用项；任何必需证据缺失时不得把生产试点标记为已批准。

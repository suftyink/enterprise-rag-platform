# 06: 原子激活候选 Release

**What to build:** 让系统管理员在核对候选身份、PASS readiness、容量和责任人后批准并原子激活候选 Release，保证切换失败时旧版本继续服务，并且激活不会自动扩大员工访问范围。

**Blocked by:** 05 / 将评测和 Readiness 绑定候选版本.

**Status:** resolved

- [x] 只有系统管理员能够提交激活批准，且批准包含试点范围、容量、监控负责人、回滚负责人和原因。
- [x] 批准记录、readiness 报告和候选 Release 必须引用同一发布指纹；任一不匹配、过期或非 PASS 均拒绝激活。
- [x] 激活在一个受并发保护的原子操作中切换 ACTIVE Release/Profile，并将原 ACTIVE 置为可回滚状态。
- [x] 激活前或提交期间出现失败时，原 ACTIVE Release 和员工服务保持不变，不产生双 ACTIVE 或半切换状态。
- [x] 激活成功后服务绑定、发布状态、审计事件和运行时可观察身份保持一致。
- [x] 激活本身不把未命中 rollout 策略的员工加入试点，也不改变管理员治理可用性。
- [x] 内部 Web 工作流覆盖拒绝激活、成功激活和故障注入后的旧版本连续性。

## Answer

系统管理员批准必须包含范围、容量、监控/回滚负责人和原因；同一数据库事务锁定 Release/Profile、降级旧指针并激活候选，成功后 rollout 默认 DISABLED，提交前失败不会改变旧活动版本。
